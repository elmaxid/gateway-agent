# v0.5.6 — Log de implementación

**Fecha:** 2026-07-28
**Rama:** trabajo directo sobre `master`
**Origen:** v0.5.5 (release anterior, mismo día) empaquetó `spec-plan`/`implement-plan`/`research-planner` como project-scoped (`.claude/`) — el usuario pidió moverlos al plugin distribuido, porque el staff de la empresa instala el plugin en cada puesto y necesita estos skills también.

## Qué se implementó

| Área | Contenido |
|---|---|
| Relocación | `.claude/skills/spec-plan/` → `plugins/gateway/skills/spec-plan/`; `.claude/skills/implement-plan/` → `plugins/gateway/skills/implement-plan/`; `.claude/agents/research-planner.md` → `plugins/gateway/agents/research-planner.md`. Ahora se instalan con el plugin en cualquier puesto, no solo en este checkout. |
| Portabilidad | 3 dependencias específicas de este puesto identificadas y removidas antes de mover los archivos: (1) `implement-plan` asumía perfiles de gateway con nombres fijos (`gpt56-terra`, `gpt56-sol`, `minimax`, `glm`) — ahora descubre perfiles configurados vía `gateway-companion.mjs setup list`, nunca hardcodea un nombre; (2) el tiering simple/complejo de frontend (terra≈sonnet, sol≈opus) se descartó — cada puesto usa su propio perfil de task configurado, con override explícito en el prompt si hace falta un modelo puntual; (3) las personas `octo:personas:*` pasaron de asumidas a best-effort — si el plugin `octo` no está instalado en un puesto, ambos skills degradan a juicio simple sin persona, no fallan. |
| Fix de test | `tests/agents-contract.test.mjs` — el contract test "todo agent .md debe tener la frase fail-loud de gateway" asumía que todo archivo en `plugins/gateway/agents/` es un forwarder Bash-only hacia el gateway. `research-planner` no lo es (Read/Grep/Glob/WebSearch/WebFetch/Write, nunca Bash, nunca toca el gateway). Test corregido para aplicar el contrato solo a agents con `tools: Bash` — la categoría real a la que aplica — en vez de a todo el directorio ciegamente. |
| Docs | README: sección "Skills: spec-plan + implement-plan" reescrita (ya no dice project-scoped, documenta discovery de perfiles/personas best-effort, agrega `research-planner.md`/`spec-plan/`/`implement-plan/` al árbol de "Estructura del proyecto"); `.claude/CLAUDE.md`: routing table actualizada a `Skill(gateway:spec-plan)`/`Skill(gateway:implement-plan)`/`Task(gateway:research-planner)` |
| Versión | bump 0.5.5→0.5.6 en los 3 archivos que se mueven juntos (4 campos de versión) — `plugins/gateway-codex` queda en `0.1.0`, sin tocar |
