## Verificación (dogfood real, no solo lectura de código)

- Instalado con `codex plugin marketplace add /opt/agent-plugin-cc` + `codex plugin add gateway-codex@agent-gateway` — el segundo comando bloqueado para el agente por el hook `codex-exec-guard` del plugin `octo` (solo permite `codex exec|--version|--help|-h|login|auth|completion` como subcomando bare de `codex`); lo corrió el usuario directo con `!`.
- `codex exec` con un prompt real → Codex detectó el skill solo y armó el comando exacto documentado: `gateway-companion task --profile gpt56-sol --harness codex --as researcher --no-write --prompt-file ... --json`.
- `gateway-companion task --harness codex --profile gpt56-sol` standalone (sin anidar dentro de otra sesión Codex) → `status: completed`, respuesta real generada por el modelo.
- El mismo comando **anidado** dentro de una sesión Codex activa (el escenario real de uso) → falló rápido sin log útil (`localLogPath: null`). `debate --models gpt56-sol,glm` anidado → `fetch failed` en ambos perfiles.
- Root cause del fallo anidado no confirmado al 100%: probablemente restricción de red del sandbox de Codex hacia el endpoint interno del router, no un bug del CLI. Documentado como limitación conocida en el skill y en el README; no se investigó más a fondo por estar fuera del scope pedido.
- De los 12 perfiles configurados, solo `gpt56-sol` (`kind: openai-chat`) tenía tokens al momento de la prueba — dato provisto por el usuario, no un bug de código.
